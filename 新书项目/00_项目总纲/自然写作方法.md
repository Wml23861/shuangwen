# 自然写作方法（本书创作规程）

> 本规程由本书第一章14个版本的送检实测（最终100%人工特征、0%疑似AI、0%AI特征）固化而来，是本项目自己的验证知识。
> 宪法第28、30条：本方法追求的是"文本自然"，过检是它的副产品，不是目标。禁止机械执行任何一条（见文末"机械执行警告"）。

---

## 一、检测器模型（先建立正确模型，否则一切白改）

1. 测的是**统计可预测性**（困惑度与突发度），不测词。删禁词、换同义词不改困惑度。
2. **逐构型打分**，不是整章打分。报告能把一段从中间劈开，一半判人工一半判疑似。必须全章无弱段。
3. 内容类型决定容错基线：纯日常+多人物对话=最宽松；独角戏+奇观+感官抒情=最严。构型不同天花板不同，不跨构型比分。
4. **同文波动±10-15%，单轮分数不做决策**，两轮稳定才动手。
5. **打地鼠规律**：修好一段，标红迁到下一段最弱处。判退步前先查被标段这轮改没改。
6. 核心实证结论：检测器把**打磨光滑的多从句长句读作AI，把不规则短句节奏读作人**。真人爆款的"流畅句长分布"（短23%/中61%/长16%）是阅读体验标准，**不是本检测器的过检目标**——按它回调会掉20个点（已证伪）。高质量与0%AI特征不冲突，冲突的是"出版物式光滑"与检测器。

## 二、文本指纹指标（每章定稿前核对）

以下为实测过检画像，第一章v14定稿数据作基准：

| 指标 | 目标区间 | 第一章基准 |
|---|---|---|
| 汉字 | 2000-2700 | 2680 |
| 短句（≤10字）占比 | 53%-63% | 55% |
| 长句（>30字） | 全章0-6个 | 6个（2%） |
| 引号句（人声） | 60句以上 | 67 |
| 问句 | 10个以上 | 18 |
| 感叹号 | 0-3个 | 0 |
| 语气词（呢吧啊嘛） | 1-5个 | 4 |
| 叙述句与对话句 | 同等短碎（"黑着。""没人应。"） | — |
| 红线 | 破折号0、省略号0、段首标点0、忽然/突然0、元叙事0 | 全零 |

长句的去处：只允许出现在**历史上从未被标色的段落**（生活流场景、人物出场、情绪铺垫），且写完必须存档送检；被标过的敏感区维持短句不动。

## 三、必标构型总表（写时即避，每条都有实测标色记录）

1. **程序流**：一步不乱的操作链（坐→流血→按纱布→等→数钱→揣怀→穿衣）。破解：插失败动作（纱布按不住两块叠着）、假警报（脚步声虚惊）、没用细节（血蹭不掉）、大白话态度（管他呢）。
2. **视觉清单接力**：静物扫描（灯→老板→电视→灯箱→红字）。破解：删除整段，信息改由人物口中报出（信息人声化）。
3. **对仗/工整递进**（含句内微型对仗）、**工整回环**（看了两遍/算了两遍）。
4. **孤立揭示句**：重要信息单独成句无依托（"顾北辰，北海之眼。"）。破解：改为短行递进分散（"喊的是顾北辰。/这名字，十年没人喊了。"）。
5. **感官接力清单**：视→听→嗅→触逐行。
6. **精致巧思句/悖论巧句**：正确去处不是换一句巧的，是让人物闭嘴。
7. **长零人声独角段**：连续十几行没人说话，尤其叠加程序流=死罪。破解：加人（路人、邻居、店员）或压到最短。
8. 其余：均匀因果链、拟人抒情、抽象觉知收尾（说不出是个什么滋味）、元叙述框架（先宣布"念头来了"再写念头）、show+tell双重处理、通用反应、排比清单、题眼多重回环、封闭单主题系统。

### 治本五问（写每一段独角戏之前问）

1. 这段里有几个人开口？零=高危。
2. 哪一拍是只有他会的？找不到=这段谁写都一样。
3. 哪一拍是谁写都有的？先删这个（消毒水味、坏灯管、喊救命、耳鸣、眼泪）。
4. 句子和段落是不是太匀了？匀=节拍器。
5. 有没有一句是作者在替人物总结？有=删，停在动作上。

## 四、正面DNA（实测判绿/判人工的构型，写作时主动执行）

1. **人声第一个进场**：开场先让人说话（两护工闲聊赌钱私事），引号句60句以上，对话驱动剧情。
2. **世俗具体细节**：物件有名有姓有价格（稳蚀剂三百八一盒、零买四十块一支、八百六十五块）。具体是人工特征最强信号。信息尽量从人物口中报出，不走旁白。
3. **失败/笨拙小动作**：纱布按不住、剪子差点没攥住、声控灯跺两脚没亮摸黑上去。人物不是每次都对。
4. **路人瞬间**：每章一到两个不推剧情的小画面（亮灯窗口小孩背乘法表卡住，大人笑他）。
5. **情绪走手走物，不给结论**：捏碎杯子、钱数了两遍第二遍手还是抖。重大情感时刻反而收着写。
6. **异样细节公式**=精确+不解释+反应克制：小牌十块一个，站那儿看了半天，卖出去四个。
7. **碎节奏鼓点**："一滴。两滴。"实测判人工。断裂句用在节拍点上（回答、停顿、转折、落定）。
8. **大白话态度**："管他呢""好家伙""还就值两千块"。叙述者有态度但作者不出面，禁总结式升华。
9. **物件跨场景携带**：棉服抢走→雨中湿透→回家挡风；药剩四顿贯穿全章。物件每次出现状态有变化，情感在变化里。
10. **人际摩擦**：误解、答非所问、各顾各的私事（雨天加倍/加倍个屁）。人不为主角的问题服务。
11. **章尾停在画面**：不总结，不预告（"鸡蛋面的钱，先留出来"）。
12. **数字要有人味**：精确到面额、到顿数、到个数，因为人记数字是为了用。

## 五、句法与对白规则

1. 基本单位是3至12字短句；意合法，删掉"于是/然后/接着/他意识到"这类焊接词，因果靠并置。
2. 主语大量省略；长句用完立刻切回短句。
3. 对白单句2至6字常见；问答经常不闭环（答非所问、反问、不答）；人物会自我修正改口。
4. 对话标签只用"X说"或不用，禁"他愤怒地说"。
5. 箴言必须是行业的话，不是人生的话；普世金句是最重指纹之一，每章至多一条。
6. 连接词不是禁品是限量品：全删到零和滥用一样可预测，偶尔不规则冒出一个"可""但是""倒"反而像人。
7. 段落长度不许均匀：一行的碎段和五六行的整段都要存在。
8. 允许有节拍功能的冗余：同义重复（"摆好，摆了又摆"）、半句自我修正、说了又咽回去。注水性冗余禁止。

## 六、番茄阅读体验层（仅供阅读体验，不作抗检测目标）

> 以下为番茄头部书实测排版特征。与第二节指纹冲突时，以第二节为准（实证：按本节句长分布回调掉20个点）。

1. 排版：一句一段为主（手机屏标准呼吸）。
2. 纯对话段落30%以上，问句是剧情发动机。
3. 解说腔松绑：每章允许一至两处叙述人直接交代人物关系，不得用于解释设定原理。
4. 网络化比喻每章至多一处；原创文学化比喻每章至多三处，其余用俗套比喻（跟冰似的）。
5. 情绪词：禁文学化重词（愤怒、绝望、悲伤、痛苦），允许番茄轻套话（心里咯噔一下、松了口气、有些无语）。
6. 毛坯嗓音：主动使用口语套话（似的、下意识、好家伙、足足、得，、化成灰都认得）。毛坯不等于注水，剧情信息密度不变。

## 七、每章创作SOP

1. 按宪法第42条十二步读取，按章节卡写初稿。
2. 初稿直接按第二节指纹指标写：短句为底、引号句60+、语气词≤5、长句尽量零、红线全零。
3. 逐段过第三节必标构型总表，独角段落过治本五问。
4. 第四节正面DNA逐条核对，缺人声加人、缺具体加价格、缺笨拙加失败动作。
5. 自检指标（字数/句长分布/引号句/问号/感叹号/语气词/红线），达标后存档送检。
6. **送检打地鼠循环**：
   - 用户送检，拿回标色截图（绿=人工，橙=疑似AI）。
   - **只删除重写标橙段**，其余一字不动（整体改方向=自杀，实测掉20个点）。
   - 标橙段处置：破程序流、信息人声化、加失败动作/路人瞬间/大白话态度，参照第三节破解法。
   - 每轮改前存档当前版本；同文波动±10-15%，单轮分数不做决策，两轮同向才定论。
   - 修到100%后，如需降低碎片感，只在历史全绿段落合并短句，被标过的敏感区不动，且保留过检存档随时回滚。
7. 定稿后更新数据库各追踪文件，版本备注只留最终结论一两行，不留过程垃圾。

## 八、机械执行警告（宪法第30条）

以下做法会把这套方法变成新的AI模板，禁止：

- 每段故意长短交替（为变化而变化）。
- 每章定额撒"生活细节"（为自然而贴细节）。
- 每章结尾强制留一个"画面"（章尾该收时就要收）。
- 故意写病句、错字、口头禅。
- 所有人物都改成惜字如金（话密的人物就是话密）。
- 反向同样禁止：全章句长压在同一区间、全章段落一般齐、每句都正确零冗余。节拍器文本本身就是最强的AI指纹。

正确原则只有一条：**让人物和故事决定语言。** 以上各节是检查清单，不是生成公式。

## 九、每章正文自检清单（第六遍语言审查时用）

- [ ] 指纹指标：短句53%以上？长句≤6个且都在安全区？引号句60+？问句10+？感叹号≤3？语气词≤5？
- [ ] 红线全文搜索：破折号0、省略号0、段首标点0、忽然/突然0
- [ ] 通读删掉"于是/然后/他意识到/他知道/他明白"（偶尔保留一两个不规则连接词不算错）
- [ ] 情绪词：文学化重词每个都必须能改成手、物、动作或轻套话
- [ ] 对话标签搜索："地说"前面的副词，删
- [ ] 金句检查：本章超过一条的，砍到一条以内
- [ ] 必标构型扫描：程序流、视觉清单、对仗旁白、孤立揭示句、长零人声独角段，逐段查
- [ ] 数字检查：涉及钱、药、数量的，是否精确到人味
- [ ] 本章是否有一至两个不推剧情的小瞬间
- [ ] 章尾是否停在画面而非预告
- [ ] 朗读检查：全文朗读速度从头到尾一致=不合格
- [ ] 设定词是否都在操作中出现，无名词解释段
